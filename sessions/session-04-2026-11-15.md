# Session 04 – Behörigheter med allow, ask och deny

**Datum:** 15 november 2026

## Mål

Konfigurera behörigheter för Claude Code så att ofarliga kontroller kan köras utan fråga, att åtgärder som kräver godkännande enligt `CLAUDE.md` alltid ger en fråga och att hemligheter och riskabla åtgärder stoppas.

## Beslut

- Ändringar i `src/` och `tests/` får göras utan fråga, inom godkända arbetsmoment.
- MCP-servrarna Gmail, Google Kalender och Canva stoppas eftersom projektet inte behöver dem.
- `git push` ligger under ask, inte deny.

## Genomfört

Claude tog fram ett förslag som jag granskade och godkände. Innan filen skapades kontrollerades syntaxen mot dokumentationen för min version av Claude Code (2.1.325, `code.claude.com/docs/en/permissions`). Det ledde till några justeringar:

- Mönster skrivs med mellanslag, till exempel `Bash(git push *)`, i stället för `:*`.
- `Read`-regler för `.env` gäller även `cat`, `head`, `sed` och omdirigeringar i Bash, så separata Bash-regler för `cat .env` behövs inte.
- `.env.*` stoppas, men `.env.example` undantas med `Read(!.env.example)`.
- `--force` stoppas även när flaggan står efter fjärrnamn och gren.
- Enligt dokumentationen ger ask-regler en fråga även i auto mode.

Filen `.claude/settings.json` innehåller 29 allow-, 47 ask- och 28 deny-regler.

| Typ | Exempel |
|---|---|
| allow | `git status/diff/log/show`, `npm run lint`, `typecheck`, `format:check`, `npm test`, `test:legacy`, ändringar i `src/`, `tests/`, `docs/`, `sessions/` och `PLAN.md` |
| ask | `git add/commit/push/tag/checkout`, `npm install`, `pip install`, `npm run format`, `db:up`, `db:reset`, `docker`, `psql`, `rm`, `mv`, ändringar i `CLAUDE.md`, `.claude/`, `package.json`, `db/`, `scripts/`, `docs/api.md`, `src/legacy/`, `jobs/`, samt WebFetch |
| deny | Läsa eller ändra `.env` och `.env.*`, läsa `*.pem` och `*.key`, `git push --force`, `git reset --hard`, `git rebase`, `git clean`, `rm -rf`, `docker compose down -v`, MCP-servrarna Gmail, Google Kalender och Canva |

Reglerna gäller både Bash och PowerShell.

## Testresultat

Inga destruktiva kommandon kördes. Deny-reglerna testades bara med torrkörningar eller sökvägar som inte finns.

| Test | Förväntat | Resultat |
|---|---|---|
| JSON-validering med `node -e` | Giltig JSON | Godkänd |
| `git status --short` | Körs utan fråga | Godkänd |
| `npm run lint` | Körs utan fråga | Godkänd, inga fel |
| Läsa `.env` med Read | Stoppas | Godkänd |
| `cat .env` | Stoppas | Godkänd |
| `git push --force --dry-run` | Stoppas | Godkänd |
| `git push origin main --force --dry-run` | Stoppas | Godkänd |
| `git clean -n` i Bash | Stoppas | Godkänd |
| `git clean -n` i PowerShell | Stoppas | Godkänd |
| `rm -rf` mot en sökväg som inte finns | Stoppas | Godkänd |
| Läsa `.env.example` | Tillåts genom undantaget | Godkänd |
| MCP-servrarna Gmail, Kalender och Canva | Tas bort | Godkänd, verktygen försvann direkt ur sessionen |
| `git commit --dry-run` | Ger en fråga | Godkänd, jag fick en fråga trots auto mode |

Reglerna började gälla direkt i sessionen utan omstart.

### Inte testat

- Ask för ändringar i `.claude/**`, eftersom testet skulle ha ändrat själva inställningsfilen.
- Deny för `git reset --hard` och `git rebase`, eftersom det inte finns någon ofarlig torrkörning. Reglerna har samma form som de som testades.

## Kända begränsningar

Behörighetsreglerna jämför texten i kommandot och är inget fullständigt skydd. Enligt dokumentationen täcker de inte:

- Kommandon i annan form, till exempel `git -C . push --force`, `sh -c "..."` eller en fullständig sökväg till programmet.
- Skript som själva öppnar filer, till exempel `node -e` eller Python som läser `.env`.
- Kommandon som läser filer utan att ange filnamnet, till exempel `grep -r` i en katalog.

Dessa luckor ska täckas av en PreToolUse-hook när hooks implementeras.
