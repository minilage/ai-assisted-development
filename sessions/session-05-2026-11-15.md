# Session 05 – Felaktig gränsförbrukning i metrics och skydd mot sen mätstart

**Datum:** 15 november 2026

## Mål

Undersöka varför rad 1 i `metrics/arbetsmoment.csv` (sessionen `81117d99…`, "Granskning av Git-ändringar och dokumentation") visar 0 % förbrukning av femtimmarskvoten. Rätta raden och se till att mätvärden som saknas inte visas som 0 i fortsättningen.

## Orsak

Förbrukningen räknas som skillnaden mellan det första och det sista kvotvärdet som statusraden (`.claude/statusline.js`, `limitWindow`) såg under sessionen.

| Fält | Värde |
|---|---|
| Sessionens start (transkript) | 12:52 |
| Statusraden mätte första gången (`first_seen`) | 16:24:23 |
| Statusraden mätte sista gången (`last_seen`) | 16:24:56 |
| Femtimmarskvot, första/sista värde | 11 % / 11 % |
| Veckokvot, första/sista värde | 1 % / 1 % |

Mätningen infördes under sessionen, cirka 16:24, och statusraden mätte bara de sista 33 sekunderna. Kvoten var redan 11 % när mätningen startade. Det värdet räknades som startvärde, och därför blev förbrukningen 0. Det rätta startvärdet går inte att räkna fram i efterhand, eftersom transkriptet inte innehåller några kvotvärden.

Tid, kostnad, tokens, rader och kontext på rad 1 påverkas inte. Claude Code skickar dem som totaler för hela sessionen, och tokens läses från hela transkriptet.

## Beslut

- Alternativ C valdes: de osäkra värdena på rad 1 töms och orsaken dokumenteras.
- Hooken ska lämna kvotfälten tomma i stället för att skriva 0 när mätningen började för sent.
- Gränsen för "för sent" är 2 minuter mellan transkriptets första tidsstämpel och statusradens `first_seen`.

## Genomfört

1. **Tester först (TDD).** Fyra tester lades till i `.claude/hooks/record-metrics.test.js`:
   - Sen start (3,5 timmar): `femtimmar_fore_pct`, `femtimmar_forbrukat_pct` och `vecka_forbrukat_pct` blir tomma. `femtimmar_efter_pct`, kostnad och tokens behålls.
   - Start efter 1 min 59 s: värdena behålls.
   - Start efter 2 min 1 s: värdena töms.
   - Kvotvärden saknas i ögonblicksbilden: alla fyra kvotfält blir tomma, inte 0.
2. **Implementation.** `.claude/hooks/record-metrics.js` fick konstanten `LATE_START_MS` och funktionen `startedLate`. Funktionen `buildRow` tömmer de tre osäkra fälten vid sen start. Slutvärdet `femtimmar_efter_pct` behålls, eftersom det är uppmätt.
3. **Rättning av data.** På rad 1 i `metrics/arbetsmoment.csv` tömdes `femtimmar_fore_pct`, `femtimmar_forbrukat_pct` och `vecka_forbrukat_pct`. `femtimmar_efter_pct` är kvar på 11.

`.claude/statusline.js` ändrades inte.

`npm run lint`, `typecheck` och `format:check` kördes inte. De omfattar bara `src/` och `tests/`, och dit hör inte hookfilerna.

## Kända begränsningar

- Utan transkript går det inte att avgöra om mätningen började sent. Då behålls kvotvärdena.
- `first_pct` mäts när statusraden visas första gången, inte exakt när sessionen startar. En liten underskattning inom 2-minutersgränsen är möjlig. Det är en uppskattning och har inte mätts.
- Hur metrics-hooken och statusraden skapades dokumenteras i Session 06. Filerna `.claude/hooks/`, `.claude/statusline.js` och `metrics/` är inte committade.
