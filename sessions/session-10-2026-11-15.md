### Nytt fynd: de 15 filerna underkänns bara på grund av radslut

- `src/` och `tests/` har exakt 15 `.ts`-filer, alltså är **alla** underkända.
- `git ls-files --eol src/result.ts` ger `i/lf w/crlf`, och `core.autocrlf` är `true`. Arkivet har LF, men arbetskopian har CRLF.
- `.prettierrc.json` anger inte `endOfLine`, så Prettier 3 kräver LF.
- `prettier --check --end-of-line crlf "src/**/*.ts" "tests/**/*.ts"` och `prettier --check --end-of-line auto` på alla tre mönstren ger "All matched files use Prettier code style!".
- Det finns ingen `.gitattributes`. `git ls-files --eol` visar 38 filer med `w/crlf`, 35 med `w/lf`, 1 med `w/mixed` och 4 med `w/none`.

Följder:
- Den kända listan med "15 filer som inte följer Prettier" gäller bara radslut, inte formatering.
- PostToolUse ger exit 2 vid **varje** Edit av en `.ts`-fil i arbetskopian. Det godkända fallet för `.ts` (3.3) kan inte visas i den riktiga körningen.
- Riggfilerna som formaterades i Session 10 skrevs med LF, och Git varnar att de blir CRLF nästa gång den skriver dem.

Att rätta det kräver en ändring av konfigurationen (`.prettierrc.json` eller en ny `.gitattributes`). Det ingår inte i steget och väntar på användarens beslut.

### Riktig körning av Stop (15–16 november, samma session, ingen omstart)

Användaren godkände att ett typfel fick ligga kvar i `src/` över ett turslut.

1. **Typfel inlagt.** `export const prov: number = "x";` lades in i `src/result.ts` med Edit. md5 var `a19485a2c63976c6a902d8433fff279b` före. PostToolUse gav inget meddelande, vilket stämmer: Prettier och ESLint godkänner raden, eftersom typfel inte är deras område.
2. **Första stoppet.** När turen slutade gav Stop-hooken exit 2, och meddelandet nådde Claude som "Stop hook feedback":
   ```
   check-code: typkontrollen (tsc --noEmit, som npm run typecheck) underkändes efter ändringar i src/ eller tests/:
   src/result.ts(6,14): error TS2322: Type 'string' is not assignable to type 'number'.
   Redovisa felet för användaren. Rätta inte filen, och rätta inte andra problem, utan godkännande.
   ```
   Claude redovisade felet och rättade det inte.
3. **Andra stoppet (`stop_hook_active`).** När Claude hade svarat slutade turen utan ett nytt Stop-meddelande, fast typfelet fanns kvar. Skyddet mot en loop fungerade (3.9).
4. **Återställning.** På användarens begäran togs provraden bort med Edit (klockan 00:06). md5 var `a19485a2…` efteråt, och `git diff --stat -- src tests` var tom.

- Stop-hooken gällde i samma session utan omstart, precis som PostToolUse.
- Instruktionen "Redovisa … Rätta inte" i meddelandet följdes. Med exit 2 fortsatte Claude, men bara för att redovisa (öppen fråga 4, alternativ a).
- Stop-hookens tid är inte mätt separat i Claude Code. Enstaka körningar av `tsc --noEmit` tog 1,6–1,7 s (se Research).
